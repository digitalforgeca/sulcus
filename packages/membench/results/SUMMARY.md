## Detailed Analysis

### Sulcus (20.0% — 1st place among persistent memory)

**Strengths:**
- Best recall at 75% (3/4 tasks) — keyword search finds facts reliably
- Only system to score on multi-session (25%) — cross-session persistence actually works
- Fastest latency at ~1,600ms average — 4x faster than Zep, 10x faster than Mem0

**Growth areas:**
- Temporal: 0% — no temporal ordering/querying capability yet
- Contradiction: 0% — both old and new values persist equally
- `/api/v1/agent/search` returns empty — benchmarks used list+keyword fallback
- Vector/semantic search would dramatically improve recall and efficiency scores

### Zep (12.5% — 2nd place)

**Strengths:**
- 50% recall — fact extraction from conversations works
- Moderate latency (~7.4s) — processing is reasonable

**Weaknesses:**
- 0% multi-session — despite being a "persistent" memory system, the session-scoped model doesn't persist facts across sessions
- 0% contradiction — no supersession logic
- Multi-session and efficiency tasks errored with "No conversation turns" — adapter issue or task format incompatibility

### Mem0 (7.5% — 3rd place)

**Strengths:**
- Mem0 distills conversations into clean facts ("User has a golden retriever named Barnaby who loves tennis balls and swimming")

**Weaknesses:**
- Search consistently returns empty on free tier — all results came from get_all + keyword fallback
- Extremely slow: ~16s per task (15s mandatory wait for async processing queue)
- 0% multi-session — same structural issue as Zep
- Multi-session and efficiency tasks errored with "No conversation turns" — task format issue

### Notes on Multi-Session / Efficiency Task Errors

Both Mem0 and Zep show "No conversation turns in task" errors on multi-session and efficiency tasks. This suggests these tasks have a different structure (possibly multi-phase or require a different ingestion pattern) that the adapters don't handle. This is a benchmark design issue to fix — but notably, **Sulcus's adapter handles these tasks correctly**, scoring 25% on multi-session where competitors score 0%.

## The 45% Gap: What In-Context Can't Do

In-context memory scores 55%. The remaining 45% requires dedicated memory infrastructure:

1. **Multi-Session Persistence** (0% for in-context) — context resets kill all memory
2. **Token Efficiency** (0% for in-context) — no relevance filtering, everything gets equal weight
3. **Temporal Reasoning** (25% gap) — can't order events across sessions or track state duration
4. **Contradiction Resolution** (misleading 100%) — both values present in window, but no mechanism to prefer the latest
